# v0.41.0 耳機、來電中斷與音訊偏好

靜音時，interrupt原本會清理聲源，卻因muted條件跳過通知main暫停。原生devicechange、sinkchange及AudioSession中斷案例均重現callback為0；正式單人／雙人也重現暫停畫面仍隱藏。現在只以recovering合併通知，silence仍先清理舊聲源，再讓既有main回呼暫停對戰；重複事件不重複通知。

正式流程另重現靜音提示蓋過通話中斷，使恢復按鈕仍可點選。audioStatus改為先呈現sessionInterrupted，再呈現muted；通話中提示中斷並禁用恢復按鈕，通話結束後仍回到原靜音狀態。未修改Sound.muted、儲存鍵、音量、主增益或淡入排程。

新增十二項瀏覽器回歸：三種事件各測一般音量與靜音共六項，以及單人／雙人各測三種事件共六項獨立正式操作。涵蓋靜音下自動暫停、通話期間禁用恢復、最新15%音量、繼續仍無聲及取消靜音後一份可聽配樂。原生檢查來源清理、RMS、峰值、主增益、舊語音取消及通知去重。新增純函式測試確認通話優先顯示且不改靜音偏好。

原生六項修正前3通過／3失敗；正式流程在首頁先啟用音訊後，兩種模式都因暫停畫面仍隱藏而失敗。修正通知後，狀態提示的純函式測試先重現2通過／1失敗，修正優先序後三項通過；連同既有控制、背景及路由流程共26項通過。完整回歸、公開站及雲端平衡結果另存發布驗收紀錄。

最初兩項未暖機的正式流程停在倒數，尚未注入路由事件；路由測試明確先以既有恢復入口建立可聽音訊前置狀態，再進入指定交錯流程。保留原冷啟動／時計停滯偵測與既有倒數測試，未藉此改動產品時間邏輯。

首輪CI的兩個整合案例各含三種事件，均耗盡整體180秒預算，分別停在開聲與離場點擊，未出現音訊斷言失敗。改為每模式／事件獨立案例，保留原時限與全部音訊、偏好斷言，去除只供下一迴圈準備的離場動作。失敗時另外保存原生音訊與頁面狀態。拆分重驗的初始化失敗發生在事件注入前，先透過既有恢復控制啟用音訊後再驗證；沒有自動重試或調低RMS門檻。

未改物理、能力值、隨機數、引擎版本、戰績格式或v1～v5重播規則。沿用原手動恢復、背景保護、尾音清理與平滑增益流程；沒有新音檔、依賴或AudioContext。

這些是原生Chrome音訊圖加路由／AudioSession事件注入測試，並非真實藍牙切換、拔插耳機或來電驗收。實體iPhone／Safari與各耳機的事件支援仍需實測；瀏覽器未提供路由事件時保留原手動恢復入口。
