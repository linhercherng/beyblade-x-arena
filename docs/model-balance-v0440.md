# v0.44.0 型號平衡追查

## 結論與範圍

原觀測旗標不是失衡判決；原報告每款728次出戰，型號等量導致攻擊／平衡型對手較多，且四組發射輸入有位置與傾角差異。新增對照後，11款在兩批不同種子下，原始與四類等權勝率皆同方向偏離：10款偏弱、皓戰猛虎偏強。對手組成可解釋部分差距，不能解釋整個差距；這個結論限下列遊戲情境，不表示實物或所有玩家操作都具有相同勝率。

僅校準這11款的耐力（STA）。另外80款、所有型號的攻擊、防禦、衝刺、爆裂耐性、重量、零件、旋向及外觀皆不改。未修改移動、碰撞、計分、亂數、15秒開場保護、末段耗轉或終結門檻。

## 實驗與判定

- 每款對其他全部90款，排除同型號鏡像造成的重複出戰；四組發射、每組四個種子、同種子／同輸入互換玩家側，共2,880場。原始勝率以所有型號等量，另外按四類各25%計算，平手均留在分母。
- 校準A為0x3782a4c1，保留驗收B為0xb719d263。先用兩批舊版確認方向；校準只用A，候選固定後才跑新版B，沒有為通過B再調值。
- 四組為雙方65%／0°／中圈／沿旋、100%／15°／外圈／內切、85%／30°／內圈／外切，以及獨立隨機力量／傾角／落點／方向；編號1、3情境在同一tick同時呼喊。
- 全v5與全v6各跑A、B；另跑A的逐款隔離對照：只有目標使用新版STA，所有對手固定v5能力。共158,400場。報告保存實際目標／對手能力、種子、兩側、情境、配對、平手及勝負終結。
- 自動門檻要求舊版A／B的兩種權重都同向越界、調整方向相符；隔離對照必須同種子、同樣本、同對手，只有自身STA不同，且改善確認方向。完整v6的A／B兩種權重均須40–60%，每場15–40秒。
- 配對的兩側不視為獨立樣本。本輪以固定情境的獨立種子重現及控制變數辨識，沒有宣稱普遍統計保證，也不將不同發射分布當作同一母體。

## 為何只調耐力

原型號能力由輪廓／軸心估值推導；防禦型STA幾乎同為72，但幾何慣量仍影響同發射能量下的初始轉速，移動驅動也會耗轉。這些估值使部分型號在對稱發射下較早停轉。偏弱型號的敗場多為停轉；皓戰猛虎則在較低慣量與巡航條件下保持較高勝率。

先對騎士重盾、暴龍霸擊、皓戰猛虎、騎士圓甲與英仙幽冥做固定對手的STA單變數掃描，再用校準A決定候選，最後補齊全部11款的隔離對照。這是遊戲數值校準，不改原廠零件的實際標示，也不把遊戲慣量當作實測量。v6沿用相同運動公式；STA只透過原本耗轉公式作用，不直接指定輸贏。

## 舊戰績與發布回歸

新對戰標示引擎v6、特性v1。v5使用`legacy-stats-v5.json`的91款原能力；v1～v4保留原有分流與能力快照，不遷移或覆寫既有戰績。44組v5案例保存6秒／12秒位置、速度、轉速、傾斜等狀態與最終結果，逐值比較JSON可表示的數值；另驗證v1～v6備份及重播。

`npm run balance:models` 可重現型號前後與隔離對照，輸出`artifacts/model-balance-investigation.json`及`.md`。`npm run balance:check`先執行既有66,708場類型／時長／終結門檻，再執行158,400場型號實驗，共225,108場；不放寬原門檻。GitHub四分片均保存這些報告，完整瀏覽器與嚴格全集合併仍為發布前提。

本輪沒有iPhone、實體藍牙耳機或來電實測；瀏覽器尺寸及音訊事件模擬不替代實機驗收。

首輪完整瀏覽器驗收在第62項停止：61成功、診斷匯出版本斷言1失敗、158未執行。產品正確匯出0.44.0，但測試固定期待0.43.0；另掃描到裝置檢查有同樣固定版本。兩例改讀產品GAME_VERSION，針對性回歸2項皆通過，不調整遊戲行為或原效能／音訊門檻。原失敗摘要、瀏覽器JSON及截圖另存，最終整套須以修正後同提交重跑。
