# v0.42.0 桌面冷啟動與 11 項失敗追查

## 根因與修正範圍

v0.41.0 的 Windows 本機重驗共 98 項，87 項通過、11 項失敗。原始紀錄保留於本機 `artifacts/route-preferences-full-final-v0410.log` 與 `artifacts/local-failures-v0410/`；沒有覆寫成通過紀錄。

在未修改產品的 Chrome 157.0.8103.78、Playwright 1.65.0 重現中，AudioContext 已回報 `running`，`currentTime` 卻仍是 0。兩個正式流程的首次 tick 分別延後約 5.45 秒與 2.79 秒，材質音效頁也觀察到約 3.02 秒與 5.04 秒。之後原生時鐘自行前進，遊戲卻已在約 1 秒時觸發 `clock-stalled`，清除聲源並停在恢復狀態；正式對戰因此自動暫停，隔離演出頁則沒有建立預期的終結聲源。

另一個材質背景／裝置案例先前進到 0.0106667 秒，接著停住，也在尚未完成淡入時被中斷。因此不能只對時鐘為 0 的情況做特殊處理。

這是本機瀏覽器啟動延遲觸發的遊戲缺陷：遊戲把「尚未完成首次淡入」與「已播放後停鐘」套用相同期限。不能將它只歸為測試環境問題，也沒有證據能將原生延遲進一步歸因於特定耳機、驅動或 CPU。

共用 Sound.update 現在只在 `recovery === 0 && currentTime < voiceReadyAt` 時採用 10 秒啟動期限，沿用原本 0.25 秒淡入門檻。startupWall 在首次 restore 固定，零星 tick 不延長期限；不是每次時鐘前進就重新等待 10 秒。完成淡入門檻後回到原 1 秒停鐘保護；路由、背景或手動恢復已增加 recovery，即使尚未完成淡入，也不取得新的冷啟動期限。暖機後沿用原本取樣空窗只寬限一次的規則，沒有無限重試或自動解除暫停。

判定沿用同一 AudioContext 的單調時鐘，沒有另設會在模式切換時重置的啟動旗標；參見 [Web Audio 規範 currentTime](https://www.w3.org/TR/webaudio-1.1/#dom-baseaudiocontext-currenttime)。

倒數仍等音訊時鐘及原淡入完成，逐字完整播放；永久不 tick 時仍清理音訊並提供手動恢復。沒有修改發射時間、物理步進、配樂音量、混音、音檔或瀏覽器啟動旗標。

## 逐項追查

| 原失敗項目 | 原始失敗點 | 判讀 |
| --- | --- | --- |
| 正式雙人背景恢復 | 尚未注入背景事件，停在 countdown | 冷啟動停鐘誤判，非背景恢復斷言失敗 |
| 正式耳機與來電流程 | 尚未注入路由事件，停在 countdown | 同上，不能據此判定耳機偏好邏輯錯誤 |
| bound 終結身份 | cutoff 讀到 350，預期 2600 | 重現同時音訊未 ready；推論可能新 cue 未建立或 getter 未更新，350 本身不能證明材質參數錯誤 |
| 快速切換材質終結 | 開場 ready 等待失敗 | 首次 tick 延後，已先進入 recovering |
| 停轉慢放材質尾音 | 開場 ready 等待失敗 | 同上，未執行到尾音恢復斷言 |
| 材質終結背景／裝置恢復 | 開場 ready 等待失敗 | 診斷先 tick 到 0.0106667 後停住，尚未完成淡入就中斷；未執行到路由故障注入 |
| 終結與勝負音效 | peak 保持 0 | 與啟動誤判清理聲源一致；此數值也可能受隔離頁的繪圖／取樣時序影響，另以原生音訊回歸確認 |
| 手機精彩重播跳過 | cueRates[0] 為 undefined | 缺少受測終結聲源；啟動中斷與短 cue 已播完都可能造成，後續分開驗證取樣與聲源清理 |
| 正式自動精彩重播 | 停在 countdown | 未執行到精彩重播或重複結算斷言 |
| 暫停離場後重新選隊 | 停在 countdown | 未執行到離場與選單配樂斷言 |
| 勝負播報中立即再戰 | 停在 countdown | 未執行到勝負播報與再次倒數斷言 |

定格頁讀取原生 AudioParam 的時機，以及重播頁在未 ready 時跨越終結點，曾列為 fixture 競態候選。首輪先維持原 fixture、斷言與門檻重跑，避免把候選推論當成已證實的第二個缺陷；當時原 11 項未加暖機手勢、重試或調低 RMS／峰值要求。後續雲端隔離頁問題與測試前提修正另列於下文。

首輪共用冷啟動修正後，原 11 項以原測試全部通過（4.6 分鐘）。後續交叉審查再補上首個極短 tick 後停住的邊界；上述 fixture 候選不構成這次追加修改的依據。

最終桌面 Chrome 的 13 項開場／倒數回歸全部通過。Windows 固定版本 Chromium 158 的對照為 11 通過、2 未過：一項在首頁等待 load 事件逾時，尚未建立 AudioContext，無法據此判定音訊邏輯；另一項紀錄為原生 context 轉為 suspended 而觸發 context-interrupted，並非 clock-stalled，遊戲保護性暫停正確。保留兩份失敗紀錄，沒有把它們改列通過，也沒有因此忽略真正中斷。未進一步證實該次載入逾時的底層原因。

測試前提隨後改為等待 DOMContentLoaded 及可操作 UI；RAF 空窗案例明確先以單次既有恢復按鈕建立正常音訊，再確認原生時鐘前進與狀態提示隱藏，才注入空窗。四個冷啟動案例仍直接開局，不預先恢復音訊。固定版本 Chromium 針對原兩個未過案例、四個冷啟動及無 Web Audio 的七項重驗全部通過，沒有自動重試或故障後補救。

核心測試最終 167 項通過，TypeScript 與正式建置通過；66,708 場平衡報告與 v0.41.0 成功 CI 的 JSON 深度比較完全一致。四類驗收勝率為 49.963%、44.678%、49.719%、48.328%；全組合與邊界時長皆符合 15～40 秒，最長約 32.87 秒。

完整本機回歸為 115／115 通過（13.4 分鐘），包含原 11 項、冷啟動／RAF 空窗、音量與路由、連續再戰、各類終結／精彩重播，以及 v1～v5 舊戰績匯入重播。

## 回歸與驗證邊界

新增純邏輯回歸涵蓋停在 0 與 0.01 秒達 5.5 秒、10 秒期限邊界、零星 tick 不延長啟動期限、淡入完成後再次停鐘，以及手動恢復不得重新取得冷啟動期限。零配樂且恢復後首字前停鐘案例使用 0.1 秒、尚未到 0.25 秒淡入門檻的時鐘，繼續驗證恢復時原 1 秒保護。

正式單人與雙人各新增真實 Web Audio 加 currentTime 讀值停在 0／0.0106667 秒共 5.5 秒的故障注入，檢查 Three、Two、One、Go Shoot 的順序、完整播放、畫面對應且沒有誤暫停。故障注入期間原生 backend 繼續運作，並非真的延後硬體時鐘。永久停鐘的瀏覽器斷言改為 12 秒以驗證新的 10 秒啟動期限，其餘門檻不變，每案例仍維持原總時限。失敗時保存原生與觀測時鐘、聲源、語音及未完成請求紀錄。

CI 加入先前未持續涵蓋的正式音訊、終結、精彩重播與立即再戰案例；前次成功 CI 已使用 39 分 15 秒，新增覆蓋後工作總預算改為 60 分鐘。

首輪雲端開場測試為 26 通過、2 超時，兩項都在 RAF 空窗案例的刻意 1.6 秒等待期間耗盡原 45 秒總預算，未到暫停或倒數斷言。新增音訊前置檢查後，軟體 WebGL 環境的準備時間較長，因此只將這組案例總預算調整為 90 秒；1.6 秒故障注入、1 秒暖機停鐘保護、倒數順序／完整性與進入 battle 的斷言門檻均不變。沒有修改產品或原 11 項測試。

後續雲端開場組 28 項全部通過。首次納入 CI 的終結／重播組為 8 通過、5 未過，暴露了隔離頁的測試前提：音訊案例同時跑完整 GPU 繪圖，點擊後才讀瞬時聲源；幾何掃描在單一同步操作內提交整段重播數百次繪圖；軟體 GPU 的完整解析度也不能直接套用原生 GPU 的兩秒取樣數。cues=0 本身不足以證明單一根因，並未據此修改產品音效。

終結音訊案例改用同一 Sound 的 audio-only 隔離頁，第一個受測 cue 前只啟用一次並等待原淡入門檻；仍檢查原生聲源、RMS／峰值與靜音／暫停清理。幾何掃描保留每個 Arena.draw、每個 instance 與每頂點檢查，預組合 P*V*M 減少重複轉換，僅在同步批次內省略 GPU 提交，try/finally 復原後實際繪圖一次。產品 Arena、音訊、物理與重播程式均未因此改動。

CI 的隔離重播頁明確使用 software-GPU profile：保留 CSS 尺寸及鏡頭比例，drawing buffer 採 0.25 倍且關閉陰影，記錄實際 GPU 字串與 framebuffer 尺寸。CI 取得至少 51 個真實畫格後檢查原畫格間隔、幾何、粒子、音效與清理門檻；這不代表產品完整解析度或實體手機效能。本機仍以原生完整 390×844、兩秒取樣驗證，第 95 百分位間隔約 16.9 毫秒。完成效能取樣後另開同種子重播才測手動終結／跳過，避免慢速環境早已播完受測 cue。

隔離頁修正後，原生 10 項、軟體 GPU profile 10 項及強制 SwiftShader 的原五項失敗案例全部通過。完整 13 項終結／重播／正式音訊／再戰覆蓋移至獨立 CI job，原平衡／模型／其餘回歸 job 全部保留；兩個 job 均通過才發布，沒有跳過測試或降低產品解析度。

物理、陀螺能力值、亂數、引擎版本、戰績 schema 與 v1～v5 重播均不變。瀏覽器故障注入不等於實體 iPhone／Safari、藍牙切換、耳機拔插或來電驗收。
