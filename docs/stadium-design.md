# SPINFORGE 競技盤模型

`src/stadium.ts` 的 `createStadium(): THREE.Group` 建立完整競技盤，供 Arena 直接加入場景。造型為本專案原創，呈現玩具實體盤的塑膠碗面、齒軌及接盤結構，並非原廠 CAD 或尺寸復刻。

盤面使用白色模塑塑膠材質，加入三圈細刻線、中央 X、兩側發射區斜線及環形校準刻度。外圈包含藍青色齒軌、間隔識別齒、煙藍透明護牆、支柱、螺絲、扣件及模具紋；下方以深色底殼、金屬包邊、冷卻肋、橡膠腳及細光條提供實體厚度。兩側 OVER 接盤用橙色，前方 XTREME 接盤用紅色，皆具斜入口、較低接收底面、側牆與末端擋板。

## 與物理場地對齊

- 碗面半徑直接使用物理模組的 `RADIUS`（4.25），表面曲線為 `y = r² × 0.024 − 0.03`，保留現有陀螺接觸高度。
- OVER 開口位於 x 正、負方向；XTREME 開口位於 z 正方向。模型不新增或修改碰撞規則。
- 側口護牆半開角 0.24 rad、前口 0.29 rad，保留合法越界中心加上陀螺半徑的空間：側向半寬 0.60 + 0.39，前向半寬 0.78 + 0.39。
- 側接盤寬 2.1，前接盤寬 2.5；接盤沿出口方向延伸，斜入口由 y 0.427 降至 0.10。全模型最高 y 約 1.041，低於 1.2 的視野限制。

## 效能與相依

目前模型共有 **41 個 Mesh／InstancedMesh 繪製物件、358 個重複零件實例，展開實例後約 33,646 個三角形**。齒、支柱、螺絲、模具紋、刻度及接盤識別箭頭皆使用 InstancedMesh；護牆與環形帶合併成少量幾何。多種零件共用材質。

模型僅使用 Three.js 幾何及材質，沒有外部圖片、網路請求、Canvas、DOM 或 TextureLoader，因此可在 Node 測試環境直接建立。透明護牆使用低透明度 MeshStandardMaterial，關閉 depthWrite，未使用 transmission、即時折射或額外後製。

41 是場景內繪製物件數，不代表完整場景每幀的 GPU draw call；透明雙面與陰影會產生額外繪製。手機實機幀率仍須由完整場景驗證。

## 驗證

`node --experimental-strip-types --test tests/stadium.test.ts`：2 項通過，涵蓋盤面射線高度、三出口中心及完整半徑邊緣的護牆淨空、出口種類、有限幾何與實例矩陣、45 個繪製物件上限、最高高度及透明材質限制。

`npx tsc --noEmit`：通過。完整戰鬥畫面、陰影及曝光由 Arena 整合後檢查；上述測試不代表已測量手機效能。
