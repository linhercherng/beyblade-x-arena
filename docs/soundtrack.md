## 循環與場景切換

- 所有音符尾音和延遲以循環方式寫入PCM，末尾的殘響可接回開頭；最前／後12ms另以平滑餘弦包絡歸零，降低MP3解碼邊界的不連續。
- `battle`與`clutch`同為E小調、144 BPM，和聲皆為8小節循環：Em×2／C×2／G×2／D×2。16及32小節長度相容，切換時以舊曲playhead對新曲時長取餘數，可保持小節與和聲相位。
- 素材資料在 `src/music-tracks.json`。`duration`為原始PCM精確樣本長度除44100，應作為循環界線；實際播放可用 `Math.min(metadata.duration, decodedBuffer.duration)`，處理解碼器重取樣帶來不到1個樣本的長度差。
- 切換選單／交戰／結算時適合以音量交叉淡化，不需要等待整首播放完。合成峰值保留餘量，仍應由runtime總混音限制器及音量控制處理配樂與碰撞音效相加的峰值。

## 重製

在專案根目錄執行：

```powershell
node scripts/render-soundtrack.mjs
```

需要PATH中的FFmpeg／FFprobe與既有Playwright開發依賴、已安裝Google Chrome。作曲音列、節拍、合成音色、固定亂數種子及混音都保存在生成器；執行會重建四首MP3、manifest、WAV與驗證記錄。請在瀏覽器回歸測試前完成生成，避免中途覆寫音訊檔。

本次未透過實體喇叭／耳機主觀聆聽，也未驗證實體手機音訊硬體。音訊檔可解碼、循環數值連續，不代表所有裝置的混音響度或主觀音色已驗收。
