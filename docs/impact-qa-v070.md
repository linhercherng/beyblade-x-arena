# v0.7.0 碰撞回饋與配樂平衡驗收

日期：2026-11-12。基準：`957fc79c2b42cc478c3d0d5a1329d6a640249876`（v0.6.0）。

## 行為

- 按碰撞衝量分輕擦（<1）、碰撞（1–6）與重擊（>=6）。金屬非整數倍共振、下滑低頻及短噪聲合成三種原創瞬態，強度另控制增益；播放速度微變化避免完全重複的機械聲，碰撞x座標控制左右聲道。
- 三個波形在AudioContext啟用時快取，單聲道.12／.17／.23秒、波形峰值.84，沒有音效檔案網路請求。同時最多6個撞擊聲部、35ms內略過同等或更弱事件，播放結束解除節點與集合參照；4倍速密集事件不會無限累加。
- 交戰／賽末點配樂bus為使用者音量×.34，選單／結算×.7；保留原本音量設定，不覆寫localStorage。撞擊以獨立duck增益在4ms內壓至.72～.30，80ms後以.085秒時間常數恢復；總音量及限制器維持原設定。時間常數是漸近恢復，不是精確85ms結束，使用[Web Audio排程](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime)。
- 火花使用圓形亮芯貼圖、橙色速度拖尾，依兩顆模型估算高度避免戰刃遮住；接觸閃光固定4個Sprite重用。360個粒子上限在事件加入時即限制，手機每次最多24個；拖尾使用固定BufferGeometry，不每撞一次建立新幾何。
- 輕擦至重擊增加火花與短促角度震動；相機lookAt後套用衰減震動，避免被原有相機阻尼濾掉。弱擊不重置正在衰減的強擊。暫停不再繼續相機阻尼，震動同相位不漂移；減少動態模式關閉鏡頭震動、接觸閃光與拖尾，只保留最多8個短暫靜態亮點。

## 驗證

- 新增4項Node測試，先觀察分層、波形、震動及配樂空間斷言失敗，再實作至通過。波形44.1／48kHz檢查有限值、非靜音、峰值及平滑收尾。
- 新增3項Chrome實際Arena／AudioContext測試：亮芯／拖尾／閃光、暫停相機精確凍結、密集事件360上限與清除；配樂音量1時重擊通道RMS大於同時段配樂1.5倍，duck降低後恢復，密集撞擊混音峰值<.95；手機減少動態無震動或閃光。
- 針對性音訊與碰撞6項通過；混音重測發現較響段落的遮蔽，已降低底音量、加快duck並增強重擊，再連續重跑3次共9項通過。這是固定測試場景的訊號比較，不代表每個碰撞或所有播放設備都達相同比例。
- 已查看碰撞定格畫面，修正最初特效被戰刃遮住及白盤上對比不足；本機圖檔`artifacts/impact-v070.png`、音訊訊號紀錄`artifacts/impact-audio-v070.json`。
- 最終 `npm test`：40項通過；`npx playwright test --reporter=line`：22項全數通過（5.0分鐘），涵蓋單人／雙人完整對戰、備份／兩代重播、音訊、碰撞、暫停／背景、模型、低幀率／像素預算、低速旋轉及開場／減少動態。`npm run build`通過，既有大chunk提示仍存在。
- 最終音訊樣本：重擊通道峰段RMS .06338、同時配樂 .01234，混音峰值 .11043；密集事件RMS .07849／.00623、混音峰值 .13610。數值為測試中的最大觀察窗，不是全曲或所有機器的響度規格。
- 唯讀審查未發現阻擋發布缺陷，確認快取／節點清理、使用者音量保存、效果池、暫停與減少動態處理。

## 界線
