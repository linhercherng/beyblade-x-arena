# Playable V2 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add independent playable Dran Sword V2 and Hells Scythe V2, preserve existing replay behavior, and publish a verified 93-top release.

**Architecture:** Reuse expansion products, per-top photo references/profiles and existing geometry-driven combat profiles. Keep the 91 original records and physics unchanged, so v1–v7 snapshots remain authoritative. Dran uses factory 3-60F; Hells uses an explicitly game-selected 4-60T, while the official revision record remains blade-only with null combo. Separate IDs and unique blade names prevent confusing old and new tops.

**Tech Stack:** TypeScript, Three.js, Node test runner, Playwright, existing deterministic balance suites, GitHub Actions, Sites.

## Scope and alternatives

Use independent data-driven models and existing physics, rather than copying old models or introducing a new physics engine. The former would miss the requested distinction; the latter would change old matches unnecessarily. Geometry and material values are photo-based game approximations, not measured toy performance.

## Task 1: Source and model data

- IDs: `bx-00-dran-sword-v2`, `cx-20-hells-scythe-v2`; both use BX blade construction and R spin.
- Files: `src/model-references.json`, `src/model-profiles.json`, `src/product-images.json`; optional localized visual refinements only if reference-driven geometry is insufficient.
- Reuse unchanged released factory photos in `public/beys/revisions/`. Inspect top/angle/full detail evidence first. Derive individual 72-point blade contours, thickness, center and colors with documented approximation.
- Add focused model tests first, observe failure, implement, then verify different old/new geometry and three-part, grounded valid meshes. Do not edit existing model entries or shared physics.

## Task 2: Playable catalog and UI

- Files: `scripts/catalog-expansion.json`, `src/chinese-names.json`, `src/catalog.ts`, `src/catalog-revisions.json`, `src/catalog-revisions.ts`, `src/main.ts`.
- Add separate products, independent blades, proper sources/dates/names, factory/game combo provenance. Map old reference cards to the playable V2 records without duplicating V2 search matches.
- Preserve official Hells combo=null; expose the game's 4-60T consistently on cards, detail and battle identity. All other stats, IDs and order stay unchanged.
- Tests: update obsolete 91-total assumptions to 93 while still asserting the exact frozen original 91; legacy fixtures remain unedited. Add V2 search, selection, 3D details, battle and replay coverage; verify desktop/mobile layout.

## Task 3: Battle traits and balance

- Reuse `combatProfile` from independent model data for contact, mass/inertia, stability and movement; existing F/T material/signature systems apply.
- Add paired calibration and independent holdout samples for each V2 against every opponent and four launch profiles, with swapped player sides. Require both raw and equal-type rates 40–60%, all observed matches 15–40s.
- Use existing `runModelTrial` and `assertModelTrial`; only tune new IDs if a confirmed issue is found. Do not retune old tops or alter time bounds/outcomes.
- Integrate the V2 gate into release balance checks. Full class balance, edge launches and all-pairs checks remain required.

## Task 4: Verify and release

- Run failing focused tests before implementation and corresponding green tests after. Run all core tests, build, native visual/functional checks, and frozen v1–v7 replay checks.
- Read-only spec review followed by code quality review; address blockers with regression checks.
- Bump app version, document official vs game scope and balance evidence. Commit, run same-commit release verification and GitHub CI without skips/flaky passes.
- Push GitHub main normally, package exact checked source through Sites, retain public audience, deploy saved version, verify served version/assets and public V2 battle/replay flows. Stop only owned preview/test processes.
- Actual toy measurements and physical iPhone remain unverified.
